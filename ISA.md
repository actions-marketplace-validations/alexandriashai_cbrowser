## Problem

Teams ship web UX that quietly loses users — they abandon carts, bail on checkout, give up on goals — and the friction isn't discovered until conversion drops in production. Traditional testing checks that a flow *works*, not whether a real person (or an AI agent) can actually *get through it* without giving up. There's no cheap, fast way to predict cognitive abandonment before shipping.

## Vision

Point cbrowser at a URL and it tells you where users will give up **before they do**: a cognitive transport score (0–1), a per-step abandonment-risk percentage, and the specific bottleneck — across 26 cognitive traits and 11 disability/behaviour personas, in ~60 seconds. Sites that pass cbrowser's cognitive tests are measurably easier for both humans and AI agents to navigate.

## Out of Scope

- **The marketing/product frontend** — lives in the sibling `cbrowser-web` repo (Next.js). Not this package.
- **Enterprise-only tools + remote/hosted MCP** — the +20 enterprise tools and the remote enterprise server live in `cbrowser-enterprise`. This ISA covers the core `cbrowser` package and its local/base MCP server only.
- **General-purpose scraping / a functional-E2E-test-runner replacement.** cbrowser is cognitive/UX analysis + agent-navigability, not a Selenium/Playwright-test substitute.

## Principles

- **Predict, don't just report.** The value is surfacing abandonment *before it happens*, not logging it after.
- **Cheap and fast enough to run often.** ~$0.05/test, results in ~60s — usable in CI and iteration loops, not just audits.
- **Accessible output is first-class.** `--no-color` / `--plain` / `--json-output` must keep every command usable for screen readers, CI, and scripting.
- **Keyless basics, keyed cognition.** Navigate/screenshot/click/extract/explore need no API key; cognitive journeys require an Anthropic key. The boundary must stay clear.

## Constraints

- **Language / runtime:** TypeScript 5.3, Node ≥18. Published as npm package `cbrowser` (bin `cbrowser` → `dist/cli.js`).
- **Browser engine:** Playwright (Chromium primary; Firefox/WebKit optional). `postinstall` fetches Chromium.
- **Protocol:** MCP-compliant tool surface (`@modelcontextprotocol/sdk`) — the 120-tool contract is a public interface.
- **Cognitive dependency:** Anthropic API (`@anthropic-ai/sdk`) for cognitive journeys; basic commands must stay keyless.
- **Economics:** ~$0.05/test target — cost is a design constraint, not an afterthought.
- **License:** MIT.

## Goal

cbrowser is a cognitive browser-automation package that simulates real user cognition — abandonment detection, constitutional safety, UX friction discovery, and AI-agent navigability — exposed as a CLI and a 120-tool MCP server, so a site can be scored and de-frictioned for both humans and agents before it ships.

- **2026-07-29** — **Selector generation interpolated raw attribute values, and one failure mode was silent.** Every selector-building path built strings like `#${el.id}` and `[aria-label="${label}"]`. Verified against a real Chromium: `#:r0:` — the exact shape React 18's `useId` emits — throws `DOMException`, as does `#2fa-code` (leading digit) and any `aria-label` containing a quote; `#a.b` throws nothing and matches nothing, because CSS reads it as `element#a.class-b`. That third case is the dangerous one: it surfaces as "element not found", so the selector looks fine in the report and the page gets blamed. Fixed with a pure-JS `src/selector-escape.ts` (pure because the same code must run in Node, where `CSS.escape` does not exist) — proven equivalent to native `CSS.escape` on all 16 probe cases before being used. Applied to 4 sites in `browser.ts` and all 8 `SELECTOR_PRIORITY` builders in `analysis/natural-language.ts`.
- **2026-07-29** — Same change, second defect: **`click`/`analyzePage` used a different selector priority than the documented one.** `find_element_by_intent` implements the published order (aria-label > role > semantic > id > name), but the three builders in `browser.ts` led with `#id` and two placed `name` above `data-testid`, with ARIA absent entirely — so the same element yielded different selectors depending on which tool asked. Aligned them ARIA-first. Beyond consistency this is a stability argument: a generated id changes between renders, an explicit `data-testid` is a contract, and an `aria-label` is the thing a user actually perceives.
- **2026-07-29** — **`cognitive_distance` returned three numbers that looked comparable and were not, plus a verdict that never varied.** `w1` (L1 sum over 26 traits), `w2` (L2 norm) and `sliced` (mean random projection) differ by ~20x end to end (measured means across all 210 built-in persona pairs: 0.296 / 0.128 / 0.016). Worse, the verdict's absolute bands (0.01/0.03/0.06) were calibrated for a scale `w1` does not occupy (0.055–0.684), so **209 of 210** pairs read "Substantially different cognitive profiles". Both fixed by one idea — express each metric as its percentile within the built-in persona population, since percentiles ARE comparable across metrics and are grounded in the real spread rather than a guessed threshold. Raw values retained for callers tracking them over time, with an explicit `scaleNote` saying not to compare them. Reference population deliberately excludes user-created personas, or the same two personas would score differently depending on what else the caller had saved.
- **2026-07-29** — `sliced` was **nondeterministic** while its MCP tool declared `idempotentHint: true` — 100 projections drawn from `Math.random()`, so identical calls disagreed by ~5%. Seeded with mulberry32 against a fixed constant. A metric a caller cannot reproduce cannot be diffed against a baseline, which is most of what this metric is for.
